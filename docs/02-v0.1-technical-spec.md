# Version 0.1 Technical Specification

## Purpose

This document defines the implementation target for Version 0.1.

The objective is **not** to build a complete game.

The objective is to build the smallest possible prototype capable of answering one question:

> **Is the movement fun enough that players want to keep playing?**

Every implementation decision should support that goal.

---

# Primary Goals

The prototype should allow us to evaluate:

* Player movement
* Grappling
* Rope physics
* Momentum preservation
* Speedrunning feel
* Control responsiveness
* Movement flow

Everything else is secondary.

---

# Technology Stack

Frontend

* TypeScript
* Phaser 3
* Vite

Physics

* Matter.js

Target Platform

* Modern desktop browsers

Build Target

* Static HTML5 build suitable for browser game portals.

---

# Architecture Goals

The codebase should prioritize:

* readability
* modularity
* configurability
* rapid iteration

The architecture should support frequent tuning without major refactoring.

Gameplay systems should remain loosely coupled.

---

# Core Systems

Version 0.1 should contain only the following gameplay systems.

## Player Movement

Responsibilities

* running
* jumping
* air movement
* landing
* momentum preservation
* bunny-hop timing window

Movement should feel responsive before additional systems are introduced.

---

## Grapple System

Responsibilities

* firing grapple nodes
* permanent node placement
* grappling nearest valid node near cursor
* rope simulation
* attaching
* detaching
* rope extension
* rope retraction

No advanced mechanics should be added yet.

---

## Weapon System

Initial weapons only:

1. Grapple Node

Places a permanent grapple node.

Consumes one ammo.

2. Explosive

Destroys destructible terrain.

Consumes one ammo.

No additional weapons should exist in Version 0.1.

---

## Level System

Responsibilities

* load JSON level
* spawn player
* goal detection
* restart
* hazards
* terrain properties

No procedural generation.

No editor.

No progression.

---

## Timer System

Tracks:

* current run
* personal best
* restart timing

The timer should update every frame.

Restart should be nearly instantaneous.

---

## Camera System

Simple smooth-follow camera.

Camera tuning should be configurable.

No cinematic effects.

# Configuration Philosophy

Gameplay values should not be hard-coded.

They should be loaded from configuration.

Examples include:

Movement

* gravity
* acceleration
* air acceleration
* jump velocity
* friction
* drag

Grapple

* rope stiffness
* rope damping
* maximum length
* minimum length
* retract speed
* extend speed

Momentum

* landing preservation
* bunny-hop window
* bunny-hop multiplier

Camera

* smoothing
* dead zone
* zoom

Weapons

* ammo
* projectile speed
* explosion radius

---

# Developer Tuning Panel

Version 0.1 must include an in-game developer panel.

Purpose

Rapid iteration.

Requirements

* adjust values live
* immediately see results
* save current configuration
* load saved configuration
* restore defaults
* organize values into categories
* no recompilation required

This is considered a core feature of the prototype.

---

# Visual Style

Placeholder graphics only.

Use simple shapes.

Examples:

* circles
* rectangles
* colored lines

Avoid spending development time on art.

---

# Audio

No custom audio required.

Simple placeholder sounds are acceptable.

---

# Performance Targets

60 FPS minimum.

Movement should remain smooth even with many grapple nodes.

Avoid unnecessary allocations during gameplay.

---

# Coding Standards

* Keep classes small.
* Prefer composition.
* Avoid giant manager objects.
* Minimize global state.
* Document why systems exist.
* Favor explicit code over clever code.

---

# Acceptance Criteria

Version 0.1 is complete when:

✓ Player movement feels responsive.

✓ Grappling functions reliably.

✓ Rope extension and retraction work smoothly.

✓ Permanent grapple nodes function correctly.

✓ Explosive projectiles destroy terrain.

✓ JSON levels load correctly.

✓ Timer and restart loop function.

✓ Developer tuning panel can modify and save gameplay values.

✓ The game consistently runs at 60 FPS.

---

# Explicitly Out of Scope

Do not implement:

* enemies
* collectibles
* procedural generation
* multiplayer
* achievements
* progression systems
* cosmetics
* story
* level editor
* portal SDK integration
* mobile controls

These will be introduced only after the prototype successfully demonstrates satisfying movement.

---

# Guiding Principle

When making implementation decisions, optimize for **iteration speed** rather than feature completeness.

Every system should be easy to modify after playtesting.

The prototype's purpose is to discover what feels great—not to lock in final gameplay.
